2. What is remaining (do this before App Store submit)

A. Production hosting (blocking)

  • Choose a real HTTPS host for the Node app (Fly, Render, Railway, Cloud Run, VM, etc.). Do not use the Shopify CLI tunnel as production.
  • TLS certificate for that host.
  • Dedicated production PostgreSQL (not the staging DB, not SQLite).
  • Automated Postgres backups.
  • Set production env vars in the platform secret store (never commit .env).
  • Generate production Shopify TOML from the real host (today shopify.app.production.upselltrix.toml still uses fgpb-ci.myexample.com — treat as a placeholder until you generate from your host).
  • Local shopify.app.upselltrix.toml correctly keeps example.com for CLI tunnel rewriting. Do not submit using that file’s URLs.

B. Git / release hygiene (blocking)

  • Review and commit the large uncommitted Shopify-app working tree on a clean branch (or discard what should not ship).
  • Review and commit marketing-site screenshot section if that site is part of listing URLs.
  • Do not deploy from mixed local tunnels + uncommitted Discount Function / storefront files unless that is the intended release.
  • Run npm run check:release on the commit you will deploy. Fix failures before deploy.

C. Shopify Partner app configuration (blocking)

  • Production application_url = your real HTTPS origin.
  • Auth redirect = https://YOUR_HOST/auth/callback (must match runtime prefix /auth, not /api/auth).
  • App proxy URL = https://YOUR_HOST/apps/proxy, subpath free-gift, prefix apps.
  • Embedded app enabled.
  • Scopes stay: read_discounts,write_discounts,read_publications,read_products unless product/legal review expands them.
  • Webhooks live on production: app/uninstalled, app/scopes_update, compliance topics.
  • Theme app extension deployed with merchant-facing name UpsellTrix.
  • Discount Function deployed with the same production app.

D. Discount-sync worker (blocking)

Creating the worker code is not enough. Production must schedule it.

  • Run npm run discount-sync:once every 1–2 minutes as a separate process (recommended), or run npm run discount-sync:watch as a dedicated process.
  • Same code version and secrets as the web process.
  • Do not embed the worker inside every web replica.
  • After go-live: npm run discount-sync:inspect shows a healthy or empty queue.

E. App Store listing (blocking for public submit)

  • App icon 1200×1200 uploaded (not logo-only feature media).
  • Paste listing copy only from docs/app-store/listing-copy.md (FINAL — SAFE TO PASTE).
  • Pricing: Free (private beta). Do not invent paid plans.
  • Privacy policy URL and support URL live (marketing site deployed).
  • Support email: support@upselltrix.algorithmtrix.com.
  • Screenshots: unique, 1600×900, real UI, clean demo store (not campaign name “ooo”).
  • Demo screencast linked.
  • Reviewer instructions pasted (fill placeholders in docs/app-store/reviewer-instructions.md).
  • Partner Dashboard automated checks actually run (session token, app URL, redirects). Do not tick them from memory.
  • Protected customer data declaration matches real scopes and storage.

F. Functional smoke on a clean store (blocking)

  • Install → Overview loads as UpsellTrix.
  • Enable theme embed on the theme you preview → save.
  • Create Spend X → Free Gift → activate → progress bar + free gift on Add to cart → cart → checkout.
  • Drop below threshold → gift removed.
  • Create a Tiered Free Gifts campaign and smoke it.
  • Mystery Gift is not creatable (coming soon only).
  • Uninstall does not error; reinstall works.
  • Shop A cannot see Shop B campaigns.

6. Detailed deployment steps (in order)

Work from the Shopify app folder:

cd C:\Users\Admin\OneDrive\Desktop\UpsellTrix\shopify-app

Use the UpsellTrix config template, not the legacy Free Gift Progress Bar default, unless you are sure you want the other Partner app:

  • Preferred template: shopify.app.upselltrix.toml
  • Legacy template: shopify.app.toml

Step 1 — Freeze the code you will ship

  1. Create a release branch from reviewed, committed code.
  2. Do not include .env files.
  3. Run the full gate (this takes a while):
npm run check:release

This runs deployment-readiness, secret scan, Prisma validate, typecheck, lint, backend/compliance/promotion/discount/storefront tests, and npm run build.

If it fails, fix the commit. Do not skip the gate for production.

Step 2 — Provision infrastructure

  1. Create the HTTPS host and point DNS at it.
  2. Create a dedicated production Postgres database and enable backups.
  3. Create a staging host + staging database if you will test there first (recommended). Never point staging at production DATABASE_URL.
  4. Put secrets in the platform secret store.

Step 3 — Validate env against that host

NODE_ENV=production ^
SHOPIFY_API_KEY=... ^
SHOPIFY_API_SECRET=... ^
SHOPIFY_APP_URL=https://YOUR_REAL_HOST ^
SCOPES=read_discounts,write_discounts,read_publications,read_products ^
DATABASE_URL=postgresql://... ^
  npm run validate:env

npm run check:deployment-readiness
npm run scan:secrets
npm run db:check
npx prisma migrate status

Replace YOUR_REAL_HOST and credentials. Do not paste secrets into chat, git, or this PDF.

Optional money-field preflight (report only, safe):

npm run money:backfill:dry-run
npm run money:verify

Run the actual backfill (npm run money:backfill) only if dry-run shows work and you have an approved change window.

Step 4 — Build the application image (or platform build)

npm run build:docker

Or use the repo Dockerfile on your platform. Do not run Prisma migrate during image build. Do not start the worker inside the web CMD. Web command is:

npm run start

Step 5 — Migrate the database (once, before traffic)

Web containers do not migrate on boot. This is an explicit release step.
  1. Backup Postgres first.
  2. Optionally pause the worker: DISCOUNT_SYNC_WORKER_DISABLED=true.
  3. Apply migrations:
npm run migrate:deploy
npx prisma migrate status

Or the same commands inside a one-shot container with DATABASE_URL set. Never run prisma migrate reset in production.

Step 6 — Start web and confirm health

  1. Deploy the image / start npm run start.
  2. Confirm:
GET https://YOUR_REAL_HOST/health/live
→ 200  { "status": "ok" }

GET https://YOUR_REAL_HOST/health/ready
→ 200  { "status": "ready" }

If ready fails, the database is not reachable or not migrated. Do not continue.

Step 7 — Schedule the discount-sync worker

Recommended (cron / scheduled job every 1–2 minutes):

npm run discount-sync:once

Alternate (always-on process):

npm run discount-sync:watch

Then inspect:

npm run discount-sync:inspect

Empty queue is OK. Overlapping run-once jobs are safe (row locks). Platform job timeout should be at least several minutes.

Step 8 — Generate and validate production Shopify TOML

This writes a deploy file. It does not overwrite local shopify.app.toml / shopify.app.upselltrix.toml (those stay as CLI placeholders).

set SHOPIFY_APP_URL=https://YOUR_REAL_HOST
set SHOPIFY_TOML_TEMPLATE=shopify.app.upselltrix.toml
set SHOPIFY_TOML_OUT=shopify.app.production.toml
npm run generate:production-toml

set SHOPIFY_TOML_PATH=shopify.app.production.toml
npm run validate:production-toml

On PowerShell:

$env:SHOPIFY_APP_URL="https://YOUR_REAL_HOST"
$env:SHOPIFY_TOML_TEMPLATE="shopify.app.upselltrix.toml"
$env:SHOPIFY_TOML_OUT="shopify.app.production.toml"
npm run generate:production-toml
$env:SHOPIFY_TOML_PATH="shopify.app.production.toml"
npm run validate:production-toml

Validation fails if URLs still contain localhost or example.com / *.example.com, or if they disagree with SHOPIFY_APP_URL.

Expected production TOML fields (example shape only):

application_url = "https://YOUR_REAL_HOST"
redirect_urls   = [ "https://YOUR_REAL_HOST/auth/callback" ]

[app_proxy]
url     = "https://YOUR_REAL_HOST/apps/proxy"
subpath = "free-gift"
prefix  = "apps"

Step 9 — Deploy to Shopify (config + extensions)

This is an operator action. It calls Shopify CLI. CI does not do this for you.

$env:SHOPIFY_TOML_PATH="shopify.app.production.toml"
npm run deploy:production

Confirm in the CLI that you are deploying the UpsellTrix app (not a leftover template app). This publishes:

  • App URLs and app proxy
  • Webhook subscriptions including compliance
  • Theme app extension (progress bar embed)
  • Discount Function fgpb-discount
Plain npm run deploy does not enforce the production TOML gate. Use deploy:production for production.

Step 10 — Install on a controlled test store

  1. Use a store that is not a real merchant, or a dedicated production-canary store.
  2. Install UpsellTrix from the Partner app install link / test store.
  3. Approve scopes.
  4. Confirm Overview loads inside Shopify Admin (embedded).

Step 11 — Merchant smoke (must pass)

  1. Theme setup → enable UpsellTrix app embed → Save (on the theme you will preview; draft ≠ live).
  2. Create a Spend X → Free Gift campaign: threshold, gift product published to Online Store, activate.
  3. On the storefront (Dawn recommended): Add to cart until the bar fills.
  4. Confirm the gift line appears and is free at checkout (cart path, not Buy it now).
  5. Remove items so spend drops below threshold; gift should come off.
  6. Create and activate a small Tiered Free Gifts campaign; confirm extra gifts as spend climbs.
  7. Reload the cart page; gift state should reconcile (no duplicates).
  8. Check App Proxy JSON in the browser network tab: /apps/free-gift/widget-state returns JSON, not an HTML error.
  9. Restart the web process; session should survive or re-auth cleanly.
  10. Uninstall and reinstall once on the test store.

Step 12 — Monitoring

  • Alert if /health/ready is not 200.
  • Alert if discount-sync:inspect shows a growing failed queue.
  • Confirm logs never print access tokens, cookies, DATABASE_URL, or emails.

7. After hosting works: App Store submission steps

Only start this after Step 11 passed on a hosted app (not the CLI tunnel).

  1. Deploy the marketing website so /privacy and /support are public HTTPS.
  2. In Partner Dashboard → UpsellTrix → App listing, paste copy from docs/app-store/listing-copy.md.
  3. Set category, Online Store required, pricing Free.
  4. Upload icon (1200×1200) and screenshots (1600×900, unique, real UI).
  5. Link demo screencast; paste reviewer instructions with real support email and optional demo store.
  6. Declare protected customer data honestly (this app reads products/discounts; it is not a customer-PII product — still complete the form as Shopify asks).
  7. Run Partner automated checks. Fix anything red.
  8. Submit for review.
Until those listing assets exist, you can still run a private beta: install via Partner “test on development store” / custom distribution. That is not a public App Store submit.

8. Rollback (if production breaks)

LayerAction
WebRedeploy the previous image. Do not prisma migrate reset.
Shopify config / extensionsRedeploy the previous CLI version from Partner/CLI.
DatabaseAdd a forward corrective migration, or approved PITR restore. Never reset.
WorkerDISCOUNT_SYNC_WORKER_DISABLED=true then inspect; clear the flag to resume.
StorefrontMerchant turns off the UpsellTrix theme app embed.

9. Local development (not production)

For laptop testing only:

npm run dev -- --config shopify.app.upselltrix.toml --store YOUR-DEV-STORE.myshopify.com

10. Hard rules

  • Do not rename cart properties _fgpb_free_gift, _fgpb_campaign_id, _fgpb_tier_id.
  • Do not change Discount Function logic as part of “just deploying.”
  • Do not list Mystery Gift, GoKwik, accelerated checkout gifts, or paid billing as live.
  • Do not use “Promotion Engine” or “Free Gift Progress Bar” as the public product name. Public name is UpsellTrix.
  • Do not guess production hostnames in git.
  • Do not run staging fixture scripts against production merchant databases.
